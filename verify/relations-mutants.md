# 規則の登録・解決を拒否する条件の検証

SQL の書き込みを拒否した際、CLI の終了コード、JSON のエラー種別・文言、SQLite の全テーブルの内容を照合する。照合にはメタデータの版、操作の受け取り、出典、全文索引の内部テーブルを含む。各提案の版 ID を show で指定して、現行版と判断待ちの状態も確認する。

| 故意に無効にした条件 | 失敗を検出するテスト |
|---|---|
| 現行版への判断待ちが残る間は言い直しを拒否する | restatement_waits_for_open_proposal_against_that_version |
| 同じ現行版への別の判断待ちが残る間は提案の採用を拒否する | adoption_waits_for_other_proposals_against_that_version |

各条件を別々に false に置き換え、該当テストが誤った書き込み成功を検出した。条件を満たすように残る提案を解決した後は、同じ操作が成功することも各テストで確認する。

## relations.rs の変異試験

Rust 1.88.0、cargo-mutants 27.1.0、Linux ARM64。専用コピーと個別のビルドディレクトリで実行する。

```sh
cargo mutants -p omoide --file crates/omoide/src/relations.rs --timeout 180 --in-place
```

拒否経路の2テストを追加した時点の初回は、変異37件中25件を検出し、5件が生き残り、7件がコンパイル不能だった。生き残った5件を次のテストで検証する。

| 初回に生き残った変更 | 追加した照合 |
|---|---|
| check_scope の parent 分岐を削除 | 全対象の親に対する例外の言い直しでは、対象なしを拒否し、新しい明示対象を受理する |
| 親の範囲判定で AND を OR に置換 | 全対象の親の下で、例外の対象を別の明示対象に変更できる |
| 子の範囲判定で不一致を一致に反転 | 親の対象を、その子と同じ対象に狭める操作は成功し、別の対象への変更は失敗する |
| plan の Pending との一致を不一致に反転 | 現行版と対象が重ならない unsure は失敗し、明示的な restated は成功する |
| plan の対象の不一致を一致に反転 | 対象が互いに異なる提案を未解決の食い違いとして登録できない |

上の照合を加えた最終実行は、同じ37件のうち検出30件、生き残り0件、コンパイル不能7件、時間切れ0件だった。等価として許容した生き残りはない。
