# Frozen evaluation plan

Use the 72 raw rule bodies, scenes, targets and actions in rules.jsonl. Domain, excludes, reasons, key phrases and query labels are never incorporated into the rule text. For each unordered pair, the lower numeric rule ID determines the split: odd = DEV, even = TEST. The link set uses the original queries.jsonl; a link is any two distinct members of the union of must and must_not on one query. Positive: identical non-null target and action, or a link within one domain. Negative: different domains with neither link nor positive label. Other pairs are unlabelled. Null is an unknown target, not a shared target. No acting or judging model participates.

For each incoming rule compare against the other 71. Report directed pairs delivered (both orientations) for recall and false alarms, plus mean/max displayed neighbours for odd and even incoming IDs and for all 72. Before/after use identical inputs and current-state snapshots. A pair hidden by the display cap is not credited as delivered. Score DEV with a conflict-first preference: exclude policies that flag the unrelated Japanese pairs or miss the ten required pairs, then prefer high positive recall without increasing the baseline DEV false-alarm rate. Report tradeoffs across coverage, lexical token filtering, action/target weighting and display budget. Once selected, do not tune on TEST.
