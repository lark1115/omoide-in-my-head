# Large workshop run

The same 48 invented opportunities ran once in all four arms (192 fresh acting sessions). The archive fingerprint, conditions and hypotheses are frozen in tests/trials-large. All 96 control sessions completed before the device sessions. The device binary was built from the merge of PR 16 (0d861ee), with 885 active rules, 627 decision versions (36 revised), 819 facts and 717 experiences in the same seeded snapshot. No actor sessions were replaced or repeated. All arms used Claude Code 2.1.329, claude-sonnet-5-5 low, 120 seconds, the same ledger contract and the same eight-second tool deadline. Grading used separate Codex CLI 0.170.0 / gpt-6.2-sol low processes. All pre-final visible agent messages were lookup announcements or continuation requests, so the final work instruction supplied the host-observed commitment time.

## Availability and timeouts

Forty of 48 sessions in each device arm attempted recall. All attempts failed to produce a recall response in two core sessions and four Jev sessions (2/48 and 4/48 assigned, or 2/40 and 4/40 callers). In ten of 40 Jev-calling sessions the agent received no successful semantic judgment; six received a core fallback without any successful Jev judgment and four received no valid recall response. The two counts measure different outcomes. The full per-lookup observations, including actual token receipt attribution and separate diagnostic timings, are in lookup-diagnostics.json. Receipt totals are in provider-receipts.json.

Five recall commands hit the outer eight-second deadline (core two, Jev three). Core has no judge. The three lost Jev responses have no original evidence of a provider exchange. Original traces cannot separate process startup from store/query preparation in these five cases. In separate warm offline replays, the same inputs produced candidate pools of 962 and 647 for core and 0, 383 and 26 for Jev. Those five replays completed in under 0.2 seconds each. The three Jev inputs also succeeded in separately labelled adapter probes. These replays do not substitute for any assigned observation.

Ten additional Jev calls reported a failed judge and a valid core fallback. Nine nonzero adapter exits were recorded; one bridge subprocess exceeded seven seconds. The original failure messages did not retain individual HTTP status codes. Separately replaying the ten corresponding adapter payloads (541–962 candidates) yielded HTTP 400 in all ten. The probe does not establish the HTTP response on the original calls. Original deadlines were 5.8 s for the adapter, 6.5 s for the local socket reader, 6.8 s for the judge port and 8 s for the tool. The one-second default port did not apply. No product reply identified the 6.8 s port as the binding deadline. Exact inner cause is unavailable for the lost outer replies.

With 885 current rules above the 500-rule scan ceiling, free-text rule retrieval used the lexical index, with the action index when supplied. Explicit action-only lookups used the action index. The separate evidence pool can take up to another 500 candidates, so the combined pool exceeded 500. Across valid-input lookups the reconstructed combined pool ranged from 0 to 962 in both arms (medians 25 core and 34 Jev). Every reconstructible count with a matching original observation agreed. Thirty successful Jev judgments accounted for 342,712 input and 45,226 output tokens across 19 provider receipts and 11 empty requests. Each successful lookup's usage was attributable by candidate count and nonoverlapping call windows on the common driver clock, or identical zero-token receipts. Consumption on failed requests with no usage receipt is unknown. No price was reported.

## Runtime diagnostic disclosure

In the five outer timeouts, Python's exception text exposed the executable and temporary database paths to the acting model. This violated the invented-content-only requirement for five tool deliveries in five sessions (two core, three Jev). After detection the runner returned a constant timeout diagnostic. The archived grades include all five assigned observations. The public release omits raw transcripts, added-input strings and machine diagnostics. Blinding neutralizes routes and internal record IDs. Publication checks scan complete changed files for host/account identifiers, actual private directories, temporary names and credential values. Subsequent runner versions also handle the bridge timeout explicitly, record an error class, and associate receipts with an opaque query digest.

## Blinding and interpretation

A copy-level audit found route names in 17 natural-language answers after the initial mechanical cleanup. Fourteen answers also explicitly dated the host's present day when evaluating invented future-dated records (six no-device, three hot-only, two core-device and three Jev-device). The editorial pass neutralized the route or runtime date but preserved the work instruction and the agent's expressed doubt about dates or evidence. One answer needed both edits. The 30 changed copies received new random tickets and fresh grades. Only final copies and final grades are released. Grading transport retries and editorial regrading did not rerun any acting session. No grade was selected based on its label.

The predeclared primary classification is harm for this run. Relative to no device, the core device gained two passes and lost six on the same 44 opportunities. Known mistakes on target opportunities were unchanged. The no-device baseline again passed 41/44; no arm exhausted the paging budget. The larger archive and capped access produced no demonstrated uplift. Timeouts, fallback, awareness of the host's date, block order, and ordinary model variation limit attribution. This experiment contains one agent model, a separate grader model, one run and invented cases.
