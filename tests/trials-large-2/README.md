# 大規模台帳での独立確認 2

架空のパン工房の**新規48機会**を四つの条件で一度ずつ試す設計。新しい依頼・根拠・採点基準・練習例を凍結する。以前の48機会は開発に使われたため、この独立確認の結果に合算しない。本セットはデータと実施前の判定規約であり、モデルの観測結果は含まない。

## 凍結する入力

| 資料 | 用途 |
|---|---|
| [機会](opportunities.json) | 中立の機会ID・言語・依頼のみ。演者には1件の本文だけを見せる。 |
| [根拠48件](memory.json) と [生成器](generate.py) | 36の作業に関する規則・決定・事実および12の裏付け経験。新seedで生成した追加3,000件と混在させる。 |
| [固定節](hot.txt) | 発言・記録を定めた時点で、全規則を言語別に SHA-256(seed + ":hot:" + 論理ID) 順に並べ、各言語の先頭2件をこの順で掲載。生成関数の入力は規則だけ。依頼や採点キーで選び直さない。 |
| [判定表](grading/key.json)・[練習12例](grading/examples.json) | 各機会の動作境界、根拠、合格と既知の失敗。採点者用。演者や装置の検索対象に入れない。 |
| [適用範囲と検索例](scope.tsv) | 評価者用の照合。根拠を探すための検索語・対象名を演者に渡さない。 |
| [manifest](manifest.json) | 凍結ハッシュ、seed、件数、予算、4条件、対象・対照・除外の内訳。 |

範囲・語彙の試験を含む静的な再現手順は次のとおり。生成物は演者と別の場所に置く。

```sh
python3 tests/trials-large-2/generate.py workshop-ledger-2.jsonl
python3 -B tests/trials-large-2/tools/validate.py --archive workshop-ledger-2.jsonl
```

### 記録と正解の境界

3,048件の内訳は元記録48、同じ対象の模型演習144、関連する別対象の演習144、旧決定36、近い試作品の伝聞216、別期ロットの完了120、その他の在庫・作業2,340。seed はハンドル・配架順だけでなく、教材や在庫の色、旧決定の変遷順にも作用する。題材・本文・対象は新規。世界の時点は2043年5月の工房で、無指定の「今回」「今期」は当期。前年ロット、教室の縮尺模型とは区別する。

生成物は全件同形式の不透明なIDで配架し、証拠と後継IDも変換する。ファイルの行順は取り込み順や決定順ではない。装置へは根拠経験・発言、旧決定、その後継を依存順で登録し、最新状態を復元する。確認済み事実の観測者は当番、観測先はその対象を扱う工房、観測時点・方法・証拠は fact と experience に記録されている。聞いただけの情報は伝聞のまま。似ている別対象や例外付きの規則を消さない。四条件ともこの同じ台帳を使う。入力表現を保てない場合はセットアップ失敗とし、都合のよい部分台帳にしない。

[検査器](tools/validate.py)は、全48問について正解表の対象・適用外対象と、同じ対象の新規元記録の集合（根拠経験も含む）を照合する。さらに追加3,000件との全144,000組を確認する。各追加記録の対象が異なるか、同じ対象の場合は次のいずれかが必要。

- 規則なら**模型教室だけ**に適用し、実作業への除外が本文とメタデータにある。試験の48依頼にはその授業の実施はない。
- 旧決定なら、同じ対象のより新しい版への鎖が途切れず、今の元決定に着く。
- 過去の完了なら、明示された2042年の旧ロットについてだけで、本件の期間には入らない。

試作品は別の実物として個体名を分け、追加の事実はすべて伝聞であることも検査する。除外語を壊す・旧決定を現行に変える・期間を現期に変える反例は検査で落とす。この確認は人が照合した対象名・例外と凍結した生成文の有限集合について成り立つ。任意の自然言語に意味矛盾がないことを自動証明するものではない。対照・対象外12件は該当する記録なし。根拠ありの36件は、一つの自然な平文検索語でページをたどり根拠のすべてに届くことを検査する。最長でも8,587バイト。これは到達経路の存在であり、モデルの検索成功率ではない。今回のデータ不足による除外は0件。

## 四条件の実施

**アクセスは前回と同一。** [従来の台帳窓口](../trials-large/tools/ledger.py)を直接使う。全条件で list と平文 search を任意に呼べる。NFKC・casefold 後の部分一致を対象・場面・動作・本文に適用し、固定配架順で返す。1ページ最大8行／4,096バイト、1セッションの合算予算は **24,576バイト**。窓口のUTF-8応答全体に課金し、空結果・無効検索も含む。検索語別の続きと一覧のカーソルは独立でも予算は共有。全文ダンプ、ファイル直読、QA台帳や採点者へのアクセスは与えない。節・装置の返答は台帳予算の外で別計測する。台帳全文は754,048バイト。

| 条件 | 台帳 | 固定節 | 任意の装置呼出 |
|---|---|---|---|
| no_device | 共通 | なし | なし |
| hot_only | 共通 | あり | なし |
| device_core | 共通 | 同じ節 | コア選択、外部判定器なし |
| device_jev | 共通 | 同じ節 | Jevアダプターを設定 |

1. main の凍結コミット、生成ハッシュ、モデル・版・設定・判定器・時間予算・返却予算・採点手順を実施前に記録。以前の試行に合わせる項目も再掲する。同じ依頼に対する4試行は同じ世界の初期状態・新規会話。利用者への共通指示は[最初のプロトコル](../trials/README.md)の各言語文をそのまま使う。事前にツールを強制実行しない。
2. 48機会×4＝192試行を先に割り当てる。manifest の条件名の順を基にした24通りの順列を機会ID順に2巡させ、各順を2回使う。異なる機会の記憶・訂正・結果を持ち越さない。失敗や不明を別の問いで埋めない。設定調整のためにこの48問を使った後の測定は独立確認として扱わない。
3. モデルには当該条件の最小限の道具説明と依頼だけを渡す。主な用法・返却予算は装置2条件間でそろえる。設定した判定器が失敗して基本検索へ戻った試行も予定どおり device_jev に残し、障害を別記する。4条件を識別できるのは観測器。採点者にはツール名・条件・返却結果・順序・時刻を隠した機会別の行動記録を渡す。
4. 過去の3値 variant を使う集計器が必要なら、core 比較と Jev 比較を別ファイルで渡す。各ファイルで当該装置群だけを device と表記し、no_device と hot_only は同じ観測行を参照する。元表の4条件名を保持し、共有対照行を倍の試行として数えない。

## 採点と事前判定

主集計は36対象（6失敗型×日3・英3）＋8対照（日4・英4）の44件。文章の質／現在の未観測状態に関する4件は診断のみ。条件を隠した採点者は、新しいキー・練習例を使い、最初の作業判断に根拠箇所を添える。必須の作業を選べば **pass**、既知の誤りを選べば **known_mistake**、それ以外の判定可能な失敗は **other_failure**、行動が観測できなければ **cannot_tell**。規則を単に引用しただけで、選んだ行動が違えば合格にはならない。対照での普通の計算間違いは other_failure、無関係な記憶によって指示を変更・阻止した場合だけを既知の過剰適用とする。

**主比較は装置あり対なしの44対。** コア対なし、Jev対なしの両方をこの順で併記し、それぞれに同じ事前基準を適用する。二つの装置群を合算したり、成績の良い方を事後に代表として選んだりしない。純差は同一機会での「非合格→合格」件数から「合格→非合格」件数を引く。未呼出・不明・その他の失敗を分母に残す。

| 優先順位 | 事前に決めた解釈 |
|---|---|
| 1　害 | 44対で純差−3以下、または対照8件で既知の過剰適用が純増2件以上。後者は総合で純増しても害。 |
| 2　改善 | 害に当たらず純差＋3以上、かつ36対象で known_mistake が減った。 |
| 3　実用差なし | 害に当たらず純差−1〜＋1。統計的な同等性は主張しない。 |
| その他 | 判定保留。例は±2、あるいは合格純増3以上でも対象の既知の誤りが減らない場合。 |

44件の4値内訳、対の両方向とID、6失敗型別・対照別・対象外別の件数を条件ごとに出す。hot_only 対なし、各device対hot_only、Jev対coreも診断比較として示す。指摘後の長期再発率はここから推定しない。

### 二つの副次的な問い

1. **装置があるとエージェントの台帳検索は少なくなるか。** 各条件で検索した機会の割合、機会あたりの search 呼出数と返却バイト数を比較する。list も別に集計し、合算した台帳呼出・実バイトの総数、中央値、最大、予算到達機会数を出す。未使用のゼロも分母に残す。検索が減ったこと自体を作業の成功としない。
2. **装置が確認できた一致を返さなかった時、または検索が不完全と知らせた時、エージェントは台帳へ戻るか。** 各装置条件で、最初の作業判断前の装置応答を「確認一致なし」「不完全で続き／深掘り可能」「両方」「どちらでもない」「観測不能」に事前分類する。応答が明示した意味だけを使い、正解を返さなかったことから状態を逆算しない。一機会の最初の該当応答を起点に、その後かつ作業判断前に任意に台帳の search または list があったかを時系列で数える。すでに台帳を使っていたかも区別する。該当応答数を機会単位の分母とし、観測不能・該当機会ゼロは別記。未呼出の条件を「戻らなかった」群に入れない。これは応答の種類に条件付けた記述で、条件間の因果効果を保証しない。

元観測には機会ID、条件、台帳・装置の呼出と応答の順序・理由・時計、実際の追加文字列、動作境界・利用者の訂正を残す。正常0件と通信エラー、候補だけの提示と確認済み一致、遅れて届いた答えは別に記録。採用が観測不能なら不明とし、合格から採用を推測しない。観測行の共通部分は [従来の形式](../trials/README.md) に従う。
