# 大きな台帳での三条件比較

小さい台帳の[最初の実測](../../verify/trials/results/counts.md)では、主集計の合格は装置なし41/44、固定節のみ41/44、装置あり42/44だった。全144試行で同じ48件を使い、台帳を通じて読んだ総量は各条件で異なる。**全員が全文を読んだという結果ではない。** 今回は、全文を読めるだけの予算がないときにも、必要な記憶を見つけて判断に使えるかを測る。

## 固定するもの

[従来のプロトコル](../trials/README.md)、[48機会の依頼本文](../trials/opportunities.json)、[盲検採点キー](../trials/grading/key.json)、[採点練習例](../trials/grading/examples.json)、[固定節](../trials/hot.txt)をそのまま参照する。各ファイルのハッシュは [manifest](manifest.json) にある。共通指示、採点ラベル、同じ機会での条件順の相殺、実施時間・モデル・採点者の設定は前回の記録に合わせて固定する。各機会×3条件は別セッション。比較可能な変更は台帳の量・内容と次節のアクセス契約のみ。小台帳とのスコア差が量とアクセス契約のどちらに由来するかは、この一条件だけでは分離できない。

## データを作る

Python 標準ライブラリのみ。生成先は評価用の一時ディレクトリにし、演者の会話・作業ディレクトリには置かない。例の出力名は任意。

```sh
python3 tests/trials-large/generate.py workshop-ledger.jsonl
python3 tests/trials-large/tools/validate.py --archive workshop-ledger.jsonl
```

入力は[元の台帳](../trials/memory.json)だけ。generator は依頼文と正解を読まない。seed・論理IDのハッシュから全件に同形式の公開ハンドルと固定の配架順を与える。観測・決定の日時は並び順とは別で、関連48件を先頭に固めない。参照IDも一緒に変換する。書式はUTF-8、キー順固定・空白なしのJSONを1行1件、末尾LF。生成物は **3,048件・778,731バイト**。ファイル全体のSHA-256は manifest の `archive_sha256` で照合する。個別のハンドルから元の台帳・採点キーに逆引きする資料を演者に渡さない。

| 追加群 | 件数 | 混同しやすい点と境界 |
|---|---:|---|
| 同じ品目の模擬作業／同じ動作の別品目 | 144＋144 | 同じ動作名で教室の教材を扱う。各指示に模擬条件と実用品への適用除外を明記。実作業に上書きしない。 |
| 改訂済みの決定 | 36 | 6対象に過去の決定各6版。古い順の後継参照が現在の原記録で終わる。歴史として読めても現行指示にならない。 |
| 似た部品・試作品の伝聞 | 216 | 本体に似た別部材の18試作ずつ。申告者を記録し、検証済みに格上げしない。 |
| 過去の完了 | 120 | 6作業×過去20ロット。対象と作業は似ていても完了は明記した2041年のロットだけ。 |
| 工房の通常在庫・作業記録 | 2,340 | 13室×15備品×3組。各組の保管規則、札の決定、当番の伝聞、台紙づくりの経験。現行の無関係な記録も多く、古い版を除くだけでは解けない。 |

**装置側にも同じ3,048件を渡す。** ホストは kind・時点・対象・適用条件・出典・確かさを保って登録する。改訂済みの版は後継の順に投入して現行状態を再現し、模擬作業の条件を通常の規則へ吸収しない。装置の内部IDと台帳のハンドルは別で、演者が show には照会で返った内部IDを使えるよう従来の手引きを全試行で統一する。台帳と装置で同じ意味を再現できない版はセットアップ失敗として記録する。似た記録だけ間引いたり、採点キーで台帳を選別したりして走らせない。

## 全条件共通の台帳窓口

ホストにだけ生成物と[参照実装](tools/ledger.py)を置く。装置なしはこの窓口のみ、固定節のみはこの窓口＋従来の hot.txt、装置ありは同じ窓口＋同じ節＋任意の装置照会。固定節は今回の48問を使って選び直さず、前回とバイト単位で同一。各会話の開始時に台帳の本文や最近の一覧は注入しない。検索例や正解に結びつくヒントは見せない。

| 操作 | 契約 |
|---|---|
| list | 固定配架順で次のページ。先頭に戻るには新しい試行が必要。 |
| search(text) | NFKC・casefold 済みの文字列が target、scene、action、text のいずれかに含まれる行だけを同じ順で返す。単純部分一致。型・日時・IDの特殊検索、正規表現、意味検索はない。 |
| 続き | 同じ正規化語の再呼出でその検索の続きを返す。list と各検索語のカーソルは独立、予算は共有。全文ダンプ・任意SQL・ファイルやDBへの直接アクセスは与えない。 |
| 返却の上限 | 1ページ最大8行・4,096バイト。試行当たり合計24,576バイト。UTF-8の実際のJSON（行全体・外枠・moreを含む）を課金する。完全な行を返し、残量に次の行が入らなければ該当ページを短くする。次に1行も入らなければ窓口を閉じ、本文0バイトとする。無効検索のエラー・空結果も実バイトを数える。 |
| 観測 | list/search の呼出数には空結果・無効入力・予算到達後の試みを含む。返したバイトを別に累積する。強制終了・輸送失敗などで応答が届かなかったら、その試行の観測可能範囲を明示する。 |

予算は生成物の約3.16%。通常の一覧で全文を読むことはできない。一方、各有根拠の機会に人が選んだ平文の検索語で、必要な原記録が全件読めるかを検証した。36機会の最大は5,806バイト。これは**経路の存在**を示す上限例で、モデルがその語を思いつくという実測ではない。演者に検索語・最大所要量・どの記録が元の48件かは知らせない。装置の出力と固定節のバイトは台帳予算に混ぜず別計測し、総入力比較には含める。

## 各機会で正解が変わらないことの確認

[scope.tsv](scope.tsv) は評価者用。48問それぞれで対象、適用外品の別名、その問いでの時間・用途の読みを原キーと独立に明記した。control／outside も省略しない。各行を3,000追加記録と突き合わせた計144,000組を validator が検査する。

1. 原48件の全フィールドが保持され、変換後の参照が対応する原物へ届くことを照合する。
2. 同じ対象・別名に当たる追加記録は、実作業を明示的に除外する教材規則、原決定へつながる失効済み版、期間を限定した2041年の完了のいずれかだけを許す。新しい現行決定・実作業指示・同じ品に対する確認済み情報なら検査失敗。対象が重なる規則については、動作名にかかわらずこの検査を行う。
3. 別対象の記録は列挙した別部材・試作・在庫に限る。伝聞は全件 reported。主語、模擬条件、旧ロットの文面は生成テンプレートに明記し、本文とタグのずれを避ける。テンプレート・対象リスト・48行の読みは人が照合し、出力と判定表はハッシュ固定する。対象や意味を任意の自然文から自動推論できるという証明ではなく、この有限の語彙と適用範囲に対する検査である。
4. 各有根拠機会の平文検索、全件一覧の予算切れ、件数・ハッシュを検査する。検索語と正解キーは演者・判定器に露出させない。

新条件から除外した機会は**0件**。48件すべてを実施し、従来からの対象外4件だけを主集計の分母から外す。

## 実施前に固定する仮説と報告項目

主比較は**同じ44機会での device 対 no_device**。主指標は盲検採点の pass の対差、すなわち「失敗→合格」から「合格→失敗」を引いた件数。各機会を1回ずつ実施し、cannot_tell・other_failure・未呼出を分母から落とさない。ここでの線は運用上の事前基準で、統計学的な有意差・同等性の保証ではない。

| 優先順 | 今回の解釈 |
|---|---|
| 1　害 | device が純減3件以上、または8対照で既知の過剰適用が純増2件以上。後者は全体で純増しても害を併記する。 |
| 2　改善 | 上記の害がなく、device が純増3件以上かつ36対象で既知の失敗件数が減少。 |
| 3　実用差なし | 害に当たらず、純差が−1〜＋1件。小標本で統計的同等とは結論しない。 |
| その他 | 判定保留（例、純増2件、または合格は増えたが既知の失敗は減らない）。 |

条件ごとに44件の4ラベル、6種類別・対照別・対象外別の件数、3条件の全ペアで両方向の変化とケースIDを出す。device 対 hot_only は検索の増分、hot_only 対 no_device は固定節の増分を見る副比較。台帳の**実返却バイト／呼出数**は条件ごとの合計・機会当たり中央値・最大と list/search 内訳、予算で次を返せなかった機会数を出す。固定節、装置の応答バイト、モデルに加えた実入力、装置照会数・失敗数・動作前の関連結果到達も別記。観測不能な採用・利用者による再指摘は不明のまま扱う。小条件に比べて台帳アクセスが本当に難しくなったかは、予算消費・結果到達・判断を組にして読む。

採点者に条件やアクセスログを見せず、従来の基準で採点後に結合する。ベースラインが再び天井なら「この大きさとアクセス条件でも上積みを実証できなかった」と報告し、事後の予算変更や除外で差を作らない。
