# 大きな保存先での到達と検索範囲

同じ照会の読み取り束に、現行版・対象・除外・種類・期間・範囲・主張の条件を適用した件数を含める。対象数、索引などを経て語彙採点に進んだ数、外部判定が完了した数は異なる。全文索引で見つからなかった場合、対象数が残っていれば検索未完了とする。確定物があれば found を維持し、並行して search.incomplete を表示する。未確認候補の見出し、本文の条件、検索範囲、案内は同じ4,000バイトを共有する。

語彙による採否の後、直接の動作一致、本文の一致、対象だけの一致を区別し、本文と対象の語の一致をそれぞれの長さで正規化して順位に使う。英語は Snowball の語幹、日本語は従来の単字・二字語を使う。日付を指定していない照会で期間つきの記録を無条件に優先しない。確定欄に既に入っている経験は、その経験を根拠にした記録の直後でも読めるようにする。既存の除外、版、確定・未確認の区別はこの処理で緩めない。

判定に回す規則・スキルには明示された動作を適用し、関連度順に束を作る。決定・事実・経験もこの口に来ていたが、従来は全種類に規則の適用を尋ねていた。種類に合う問いで判断する。確認済みの事実か、同意が成立したかは確率から推定しない。各束の版IDを独立に検証し、完了分の確率を統合してから全体の順位を決める。1件が入らなければその件数を記録し、ほかの候補へ進む。全体の期限または失敗で止まった場合、完了分の否定結果も尊重し、残りだけ基本検索で評価する。

測定は対話モデルを使わず、初回応答だけを対象にする。固定の48原記録を含む入れ子の48・500・3,048件に、実際の照会と依頼原文を入力する。奇数機会を開発、偶数機会を独立確認に使う。採点ラベルは入力にも選定基準にも使わない。
