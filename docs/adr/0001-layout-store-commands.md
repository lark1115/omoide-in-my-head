# ADR-0001: 部品の分け方、保存の口、表、順位付け、命令

- 状態: 確定（最初の実装の入力）
- 関係する要件: DOC-OMOIDE、REQ-STORE-1、REQ-REC-1、REQ-RULE-1、REQ-DEC-1、REQ-PROMO-1、REQ-RECALL-1、REQ-JUDGE-1、REQ-HOT-1、REQ-MEASURE-1、REQ-INTEG-1、REQ-RES-1

## 決定 1: 部品は 3 つ。核は入出力を持たない

| 部品 | 役目 | 持たない物 |
|---|---|---|
| `omoide-core` | 文の区切り、当たりの点、順位付け、近い決まりの判定、登録の結果の決定、関門、量の上限に収める整形。全部、純粋な関数 | ファイル、時計、乱数、通信 |
| `omoide-store` | 保存の口（決定 2）と、SQLite の実装。表の定義と移行 | 判断 |
| `omoide`（実行ファイル） | 命令（決定 6）。時計、識別子、設定、判定の層の起動、ファイルへの書き出し | — |

時刻と識別子は、実行ファイルが作って核へ渡す。核の関数は、同じ入力に同じ出力を返す。性質の試験と全数の列挙を、核に当てる。

## 決定 2: 保存の口は 2 つ。どちらも束で、読みは 1 つの時点から取る

```
read_batch(問い合わせの束) -> 行の集まりの並び（全部、同じ 1 つの時点の中身）
exec_batch(文の束)         -> 成功 | 失敗の種類（全部か、無か）
```

D1 には、読んだ結果を使って続きを書くトランザクションが無い。そこで、読んでから書く操作は、次の形にする（REQ-STORE-1 (e)）。

1. `read_batch` で、判断に使う状態の全部と、保存の版の番号を、**同じ束で**読む。SQLite では 1 つの読みのトランザクション、D1 では 1 つの batch である。状態と版の番号を別々の呼び出しで読んではいけない（下の「試したこと」の 3 行目）。
2. 核が、書く文の束を決める。
3. 束の先頭に、「版の番号が、読んだ時と同じである」ことを検査する文を入れる。束は、版の番号を 1 つ上げる。
4. 版が合わずに失敗したら、1 からやり直す。間を空けてやり直し、全体の時間の上限を超えたら、「ほかの書き込みと重なった」と返す。

検査の文の形は、1 つに固定する: NOT NULL の列へ、`CASE WHEN (版の番号を引く副問い合わせ) = ? THEN 1 ELSE NULL END` を入れる。版の行が無い時も NULL になり、失敗する。条件に合わない時に 0 行で成功する形（`UPDATE … WHERE`、`INSERT … SELECT … WHERE`、`OR IGNORE`）は、検査に使わない。自前の関数とトリガーは使わない。1 つの束を、複数の API の呼び出しに分けない。

`exec_batch` の失敗は、種類を分けて返す: 版が合わない／待ち時間の上限／入力が縛りを超えた／容量が足りない／結果が分からない。やり直すのは、版が合わない時だけである。

### 送り直し

- 書き込む命令は、操作の識別子を受け取る（呼び出した側が渡す。渡されなければ、実行ファイルが作って結果に付ける）。
- 束は、本体の変更と一緒に、操作の識別子、入力の要約値、確定した結果を、受け取りの表に書く。
- 同じ識別子の 2 回目は、保存した結果を返す。同じ識別子で入力が違う時は、失敗にする。
- 結果が分からないまま終わった時、呼び出した側は、同じ識別子で送り直す。新しい識別子で送り直さない。この手順を、手引きに書く。

### 2 回に分かれる登録（REQ-RULE-1 (e)）

- 1 回目は、近い決まりの並び（それぞれの版の識別子）と、その並びの要約値を返す。何も書かない。
- 2 回目は、関係と、どの決まりに対する関係かと、1 回目の要約値を受け取る。装置は、同じ束の読みで近い決まりを出し直し、要約値が違えば、何も書かずに、新しい並びを返す。古い並びに対して選んだ関係を、別の版に当てはめない。

### 検査を入れない書き込み

検査を入れず、版の番号も上げないのは、呼び出しの記録だけである。

「使った」「成否」「指摘」の知らせは、知らせの識別子を持ち、同じ識別子を 1 回に数える。これらは、保存の版の番号とは別の、「使った回数の版の番号」を 1 つ上げる。常に読み込まれる節が古いかどうかは、保存の版の番号、使った回数の版の番号、設定の要約値の 3 つで決める（決定 7）。記録の状態を変える操作（スキルを候補へ戻すなど）は、検査を入れた束で行う。

### 試したこと

SQLite 3.51（Python の sqlite3、WAL、待ち時間 5 秒）で、次を確かめた。

| 試し | 結果 |
|---|---|
| 古い版の番号で束を実行する | 束の全部が取り消された。版の番号も上がらなかった |
| 9 個の別プロセスが、読んでから書く束を、各 100 回くり返す。1 個は、38 回目の束の途中で強制終了する | 書けた束は 837 個（800 + 37）。行は 837、版の番号は 837、重複は 0。途中で止めた束の行は、残らなかった。やり直しは、プロセスごとに 64〜154 回 |
| 状態を読んだあと、別の接続が状態を書き換え、そのあとで版の番号を読んで束を実行する | 検査は通り、古い状態から決めた中身が保存された。**状態と版の番号を別々に読む実装は誤りである** |

2 行目は、どの呼び出しも必ず成功することの証明ではない。重なりが続けば、上限で「重なった」と返る呼び出しはあり得る。

試していない物: `rusqlite` からの実行、D1 の実物、Turso の実物。実装の時に、同じ試しを契約の試験として書く。D1 で読みの複製を使う時は、古い読みをくり返さない読み方（主の側を読む、または続きの印を使う）が要る。対応を掲げる時に決める。

## 決定 3: 保存する物

表の名前と分け方は、実装が決めてよい。次の物が保存されるか、保存した物から 1 通りに組み立てられること。

| 物 | 中身 |
|---|---|
| 版の番号 | 保存の版の番号、使った回数の版の番号、表の定義の版、保存の識別子 |
| 発言 | 本文、時刻、話した者の種類、対象（あれば）。更新と削除をしない |
| 記録 | 記録の識別子（版をまたいで同じ）と、版の識別子（版ごと）。種類、状態（今の版／候補／判断待ち／置き換え済み／退けた）、本文、場面、場面の別の言い方（複数可）、対象、目的、当てはめない範囲、置き換えた版 |
| 決めたことの欄 | 発言の種類、決定の状態、時点 |
| 事実の欄 | 確かさの種類、確かめた場所・時刻・方法、範囲、期間、証拠の参照先 |
| スキルの欄 | 本文の参照先、失敗の回数 |
| 結びつき | 記録と動作の名前。記録と出どころ（発言か経験。種類つき）。例外と、その元の決まり。判断待ちと、その相手の決まり |
| 探すための列 | 記録の版の識別子、2 文字ずつ区切った文、1 文字ずつ区切った文（どちらも空白区切り） |
| 受け取り | 操作の識別子、入力の要約値、確定した結果 |
| 知らせの記録 | 知らせの識別子、種類（返した／使った／動作した／成否／指摘）、記録の版の識別子、機会の識別子（あれば）、呼び出しの識別子、時刻 |
| 呼び出しの記録 | 呼び出しの識別子、時刻、種類、かかった時間、返した量、機会の識別子（あれば）、問い合わせの文（設定で残す時だけ） |

- 記録を改める時は、新しい版の行を足し、前の版の状態と「置き換えた版」だけを書き換える。本文は書き換えない。
- 出どころが要る記録（REQ-REC-1 (b)）を、存在しない出どころで登録しようとした束は、検査の文と同じ形の文で失敗させる。
- 全文検索の索引の作り方（SQLite と D1 の FTS5、Turso の Tantivy）は、保存の実装が持つ。核が渡すのは、区切り済みの文だけである。
- 装置が呼ばれなかった試行と、常に読み込まれる節だけの試行は、装置の保存には入らない。比べるための道具の側が持つ（REQ-MEASURE-1 (g)）。

## 決定 4: 候補の集め方と、当たりの点

保存の全文検索は、語が 1 つも重ならない記録を返せない。あとから順位を付け直しても、集まらなかった記録は救えない。そこで、候補の出どころを分ける。

| 候補の出どころ | 対象 | 集め方 |
|---|---|---|
| 動作の名前 | 決まり、スキル | 結びつきから直接引く。全文検索を通さない |
| 全件 | 今の版の決まりとスキル | 件数が上限（設定の値。既定 500）以下なら、全部を核が採点する。判定の層がある時は、全部を判定の層へ渡す |
| 全文検索 | 決めたこと、事実、経験。上限を超えた時の決まりとスキル | 区切った語で引く。件数の上限で打ち切った時は、結果に「候補を打ち切った」と付ける |
| 結びつき | 判断待ち、例外 | 候補に入った今の版の決まりに結びつく物を足す |

- 区切り: 文字の正規化（NFKC と小文字化）のあと、日本語の文字の並びを 2 文字ずつずらして区切る。1 文字だけの並びは、1 文字の語にする。1 文字ずつの語は、別の列に入れ、問い合わせの語が 1 文字の時にだけ使う。英数字は、そのまま 1 語にする。記号は語にしない。
- 当たりの点: 問い合わせの語の集まり（重複を除く）のうち、記録の文（本文、場面、場面の別の言い方）に含まれる語の割合。記録の全体の統計を使わない。候補が 1 件増えても、ほかの 2 件の点は変わらない。
- 保存が返す点（bm25 など）は、最後の順位に使わない。全文検索の候補を打ち切る順にだけ使う。
- 場面の別の言い方: 登録する LLM は、その決まりが要る場面を、違う言葉でいくつか添えられる。語が重ならない言い換えを、判定の層なしで拾うための手である。
- 言い方の違う問い合わせ（REQ-RECALL-1 (e)）は、固定した場面で、候補に入った割合と、最後に返った割合を、判定の層あり・なしで別々に測る。通らない場面を、語の重なる問題に差し替えない。未達として記録し、意味の近さの検索を別の ADR で足すかを決める。

## 決定 5: 順位付け、例外、近い決まり

- 絞る: 今の版であること、対象が合うこと、当てはめない範囲に入っていないこと、期間と範囲が合うこと（事実）。
- 例外: 例外の対象に合う問い合わせには、例外を返し、元の決まりは返さない。結果に、元の決まりの識別子を付ける。例外の対象に合わない問い合わせには、元の決まりだけを返す。
- 順位の鍵（上から順に比べる）: 動作の名前で結びついた決まり → 利用者の決定と、自分で確かめた事実 → 当たりの点（判定の層がある時は、その答え）→ 使った回数（頭打ちあり）→ 新しさ（半減）→ 識別子。
- 判定の層が失敗した時、または答えに欠けや重複がある時は、核の当たりの点に戻る。
- 近い決まり（REQ-RULE-1 (c)）の初期方針（この項目は [ADR-0004](0004-registration-neighbors.md) が改訂）: 動作の名前が 1 つでも重なる、または、区切った語が決めた数以上重なる今の版の決まり。この線は、問い合わせの順位の線とは別に持つ。
- 登録の結果は、近い決まりの有無と、選ばれた関係から、核の関数が決める。組み合わせは、全数を列挙して試験する。

## 決定 6: 命令

| 命令 | 役目 | 要件 |
|---|---|---|
| `omoide init` | 保存先を作る | REQ-INTEG-1 |
| `omoide say` | 発言を、原文のまま入れる | REQ-REC-1 |
| `omoide rule add` | 決まりを登録する。近い決まりがあれば、それを返して終わる（何も書かない）。関係を添えた 2 回目の呼び出しで、登録を終える | REQ-RULE-1 |
| `omoide resolve` | 判断待ちに、利用者の判断を登録する。判断待ちの版の識別子と、採る方を指定する | REQ-RULE-1 |
| `omoide decide` / `fact add` / `event add` | 決めたこと、事実、経験を入れる | REQ-DEC-1、REQ-REC-1 |
| `omoide skill propose` / `skill confirm` / `repeated` | スキルの候補、確かめ、くり返された経験の一覧 | REQ-PROMO-1 |
| `omoide recall` | 問い合わせ。場面、動作、対象、期間、範囲、時間のかかる探し方、続きの印 | REQ-RECALL-1 |
| `omoide used` / `acted` / `outcome` / `corrected` | 使った、動作した、成否、指摘を知らせる | REQ-PROMO-1、REQ-MEASURE-1 |
| `omoide show` | 識別子で、本文の全体、出どころ、履歴を引く。量の上限は当てない | REQ-REC-1 |
| `omoide hot init` / `hot export` / `hot status` | 節の印を置く。節を書き出す。節が古いかを答える | REQ-HOT-1 |
| `omoide stats` | 回数、指摘、検査に変える候補を出す | REQ-MEASURE-1 |
| `omoide eval run` / `eval diff` | 決めた場面を流す。2 つの版を比べる（認めた違いは、ファイルで渡す） | REQ-MEASURE-1 |

- どの命令も、機械が読める形（JSON）を選べる。失敗は、0 でない終了コードと、理由の種類と文で返す。
- `rule add` の 1 回目（近い決まりを返しただけ）と、登録が終わった時は、結果の種類で区別する。同じ「成功」にしない。
- `recall` の量の上限は、JSON の全体（続きの印と、返していない数を含む）に当てる。続きの印は、保存の版の番号と、順位の位置を持つ。続きを取る時に保存の版が変わっていたら、「探し直した」と付けて、最初から返す。
- 1 件の記録が上限に収まらない時は、本文を文の切れ目で切り、「切った」の印と識別子を付ける。対象、当てはめない範囲、条件の欄は切らない。切った本文を、そのまま実行する指示として扱わないことを、手引きに書く。

## 決定 7: 常に読み込まれる節の書き出し

- 節の先頭に、保存の識別子、保存の版の番号、使った回数の版の番号、設定の要約値を書く。`hot status` は、この 4 つを今の値と比べて、古いかどうかを答える。
- 書き出しは、対象のファイルごとの鍵のファイルを取り、鍵の中でファイルを読み直し、印の外を写し、同じ置き場の一時ファイルに書いて、名前の付け替えで置き換える。保存の版が、読んだ時から変わっていたら、読み直す。
- 鍵を取らない書き手（人のエディタ、ほかの道具）との重なりは、守れない。この限界を、手引きに書く。
- 印は、`hot init` が明示で頼まれた時にだけ置く。印の無いファイルへ、`hot export` は書かない。

## 決定 8: 判定の層とのやり取り

実行ファイルは、設定された命令を別のプロセスとして起動し、標準入力へ、問い合わせの文と、候補の並び（版の識別子と文）を JSON で渡す。標準出力から、版の識別子ごとの答え（0 から 1 の数）を JSON で受け取る。時間の上限と、出力の大きさの上限を置き、超えたらプロセスを止める。設定が無ければ、起動しない。

| 判定の層の返事 | 扱い |
|---|---|
| 全部の候補に答えがある | 使った |
| 答えが 0 件（どれも線を越えない）で、形は正しい | 使った。当てはまる物が無い、は探した結果が 0 件の時だけ |
| 候補の欠け、重複、知らない識別子、壊れた JSON、時間切れ | 失敗した。核の当たりの点に戻る |

核と保存は、通信の部品に依らない。Jev の付け方は、別の部品として、あとで足す。

## 決定 9: 作る環境と、配り方

- Rust は 1.88 以上。SQLite は `rusqlite` の同梱版（FTS5 つき）。
- Turso の実装は、別の feature にする（Rust 1.90 以上が要るため、既定のビルドに入れない）。D1 の実装は、対応を掲げる時に足す。
- Linux（x86_64、aarch64）の、1 つで動く実行ファイルを配る。
- CI は、lint、型の検査、ビルド、`miwa check`、命令が起動する最小の検査に限る。重い試験（重なる書き込み、変異の検出）は、PR の前に手元で回し、結果を PR に書く。

## 決定 10: 作る順と、役目

| 段 | 中身 | 終わりの条件 |
|---|---|---|
| 1. 最小の一巡 | 核の区切りと点、保存の口と SQLite、`init`、`say`、`rule add`（近い決まりが無い道と、近い決まりを返す所まで）、`recall`（動作の名前と、場面の文）、`show` | 新しいプロセスと新しい会話から、S1、S2（当たる例と、当たらない例）、S6 が通る。`show` で元の発言へたどれる。README と AGENTS.md の手順を、実装した者とは別の者がなぞって、REQ-INTEG-1 (a) の一巡を終える。Linux で、起動を含む時間（中央の値と遅い側）、最大のメモリ、候補の件数を、まれな語／よく出る 1 文字／動作の名前だけ／語が重ならない、の 4 通りで測る |
| 2. 登録と履歴 | 関係を添えた 2 回目の登録、`resolve`、判断待ち、言い直し、例外、送り直し、重なる書き込み、要約の事実を入れる最小の `fact add` | S7、S10 が通る。S11 のうち、版と出どころの食い違いが無いこと。保存の契約の試験（重なる書き込み、途中で止めた時、送り直し）が通る |
| 3. 事実と知らせ | `decide`、`fact add`、`event add`、`used`、`acted`、`outcome`、`corrected`、`stats` | S3、S4、S5、S8 が通る。S11 のうち、回数の書き込みに失敗しても決まりが失われないこと |
| 4. 節、判定、関門、測る | `hot`、判定の層の口、`skill`、`repeated`、`eval` | S9（履歴と上限を合わせて）、S12（基本の探し方が成功する形で）が通る。経験 → 候補 → 確かめ → 使った → 次の順位と節に出る、の一巡（REQ-PROMO-1）。装置あり・なしの比べ（REQ-MEASURE-1 (e)〜(g)）。REQ-INTEG-1 (b) の Muse の VM と、Muse でない Linux での一巡 |

- 対応を掲げる保存を足す時（Turso、D1）は、REQ-STORE-1 (i) の試験を、その実物で通す段を別に置く。
- 実装は、ワーカーが、ブランチと PR で行う。設計した者は実装せず、自分で検査を回して、要件ごとに合否を出す。
- 場面 S1〜S12 の試験のデータと正解は、実装するワーカーとは別の者が作る。

## 決めないこと

- 意味の近さの検索（決定 4）。
- 回数の線（何回のくり返しで一覧に出すか）。設定の値にして、既定を仮に置く。
