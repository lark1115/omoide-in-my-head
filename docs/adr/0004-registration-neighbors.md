# 登録時の近い決まり

ADR-0001の決定5のうち、登録時の近傍条件を改訂する。照会の順位・閾値には適用しない。比較の目的は矛盾や例外を人に見せることにあり、点数から置き換えや例外を自動決定しない。

1. 現行版の規則を、既存の動作索引と語の索引から広めに取得する。本文・場面・別表現は従来どおり正規化する。登録比較だけ、ひらがなだけの語と一般的な英語の機能語を計算から外す。本文と場面がともに完全一致なら、ひらがなだけの記述も含め最優先の300点とする。
2. 二つの語集合の共通数を短い側の語数で割り、百分率を切り捨てる。採用には少なくとも1語、両側の構造化された対象名・動作名以外の共通内容語が要る。ADR-0002と同様に場面から識別子を差し引き、共通する発動条件の語ごとに8点（2語まで）を加算する。動作の一致で8点、さらに対象名が等しく、その名前の語または漢字が両方の場面でも重なると8点を加える。空でない本文内容語集合または発動条件集合が等しいと100点を加える。合計25点以上を比較に残す。
3. 異なる対象名（片方の未指定を含む）でも、同じ動作で双方の場面に同じ対象語が書かれていれば、少なくとも25点で残す。ここでは対象名がある側についてその名前にも含まれる英数字の語または漢字を照合し、動作名自体と「時・前・後・際・中・場・合」の単字を除く。単なる構造化タグの一致では成立しない。
4. 点数降順、同点は場面、本文、版IDの順で整列する。9件までを元発言と一緒に表示し、残りは near_remaining に数える。9は開発用の比較で、内容で選んだ候補を落とさなかった最小の枠だった。表示できない版を推測で選ぶことはできない。
5. near_digest は表示前の全候補の版の並びに結び付ける。表示外の追加・削除でも新しい比較を要求する。初回の提示では書かず、確定には関係・表示された版・要約値をそろえる。スキルの確認にも同じ手順を使う。

語がまったく違う言い換えや異言語の関係は取りこぼし得る。機械ラベルに含まれる「同じ分野の紛らわしい別物」をすべて同じ決まりとして扱うこともしない。独立確認値と日本語の対例は verify/near と tests/near に置く。
