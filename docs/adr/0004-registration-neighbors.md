# 登録時の近い決まり

ADR-0001の決定5のうち、登録時の近傍条件を改訂する。照会の順位・閾値には適用しない。比較の目的は矛盾や例外を人に見せることにあり、点数から置き換えや例外を自動決定しない。

1. 現行版の規則を、既存の動作索引と語の索引から広めに取得する。本文・場面・別表現は従来どおり正規化する。登録比較だけ、ひらがなだけの語と一般的な英語の機能語を計算から外す。本文と場面がともに完全一致なら、ひらがなだけの記述も含め最優先の300点とする。
2. 二つの語集合の共通数を短い側の語数で割り、百分率を切り捨てる。採用には少なくとも1語、両側の構造化された対象名・動作名以外の共通内容語が要る。ADR-0002と同様に場面から識別子を差し引き、共通する発動条件の語ごとに8点（2語まで）を加算する。動作の一致で8点、さらに対象名が等しく、その名前の語または漢字が両方の場面でも重なると8点を加える。空でない本文内容語集合または発動条件集合が等しいと100点を加える。合計25点以上を比較に残す。
3. 異なる対象名（片方の未指定を含む）でも、同じ動作で双方の場面に同じ対象語が書かれていれば、少なくとも25点で残す。ここでは対象名がある側についてその名前にも含まれる英数字の語または漢字を照合し、動作名自体と「時・前・後・際・中・場・合」の単字を除く。単なる構造化タグの一致では成立しない。
4. 点数降順、同点は場面、本文、版IDの順で整列する。9件までを元発言と一緒に表示し、残りは near_remaining に数える。9は開発用の比較で、内容で選んだ候補を落とさなかった最小の枠だった。表示できない版を推測で選ぶことはできない。
5. near_digest は表示前の全候補の版と点数の並びに結び付ける。表示外の追加・削除でも新しい比較を要求する。初回の提示では書かず、確定には関係・表示された版・要約値をそろえる。スキルの確認にも同じ手順を使う。

語がまったく違う言い換えや異言語の関係は取りこぼし得る。機械ラベルに含まれる「同じ分野の紛らわしい別物」をすべて同じ決まりとして扱うこともしない。独立確認値と日本語の対例は verify/near と tests/near に置く。

## 第2回改訂　保存先での頻度と場面の裏付け

初期の25点による候補集合に、以下の条件を加える。対象は登録とスキルの確認で、照会の採点は従来どおり。

- 読み取り束の中で、現行規則の総数 N と、提案に含まれる語が各々何件の現行規則にあるか（df）を数える。1件に何度書かれても1件と数える。スキル・候補・失効版は母数と分子から除く。既存のFTS5索引を使用し、スキル確認時は保存済み候補の索引語を使う。スキーマの変更はない。
- 語の重みは 100 から 200 × max(df−1, 0) / max(N−1, 1) の整数部分を引き、下限を0にする。比較中の1件だけでは頻出とみなさない。場面末尾の「場面」「場合」「とき」「時」「際」は発動条件の手掛かりから除く。
- 近いと判定するには、両場面で重み75以上の独立語が重なり、場面の共通語の重み合計が短い側の条件語数×20以上、かつ本文・場面・別表現全体で識別子を除いた共通語の重み合計が短い側の内容語数×4以上であることを求める。呼び手が明示した別表現の強い一致は場面の裏付けに代えられる。
- 前段の比較を通り、本文と場面がともに完全一致する場合、同じ本文に重み75以上の独立語がある場合、または空でない独立した場面の語集合が等しい場合は、同じ条件の例外・矛盾を落とさないために残す。異なる対象名の共通部分を用いる従来の経路にも重み75以上を求める。動作名だけからは候補を採用しない。通常の点数から、共通内容語が頻出である分を短い側の内容語数で割った値を引く。完全一致の経路では元の点数を保つ。
- 並びの要約値には、表示外も含む全候補の版IDと点数を入れる。別の規則の登録で頻度が変わり、同じ版を同じ順に表示しても点数が変われば比較をやり直す。登録は既存の版ガードを通し、読み取りと書き込みの間に状態が変われば新しい状態で計算する。

独立確認の頻出語群では依然15件中11件に誤確認が出た（最大2件）。定型手引き群は10件すべて誤確認なし。分野内の広い正例の取りこぼしも残る。実測は verify/near/store-context に置く。
